# Agrobridge

Мониторинг состояния посевов по спутниковым снимкам Sentinel-2: временные ряды
NDVI/NDMI по контуру поля, растровая карта индекса внутри поля с выделением
просевших участков, прогноз на две недели и выгрузка отчёта.

## Запуск

```bash
pip install -r requirements.txt
streamlit run app.py
```

Интерфейс откроется на `http://localhost:8501`. Если в репозитории есть папка
`data/snapshot/`, приложение сразу стартует на **настоящих данных Sentinel-2** из
сохранённого снимка — без ключей и без интернета.

Дополнительно:

```bash
python test_connection.py     # проверка доступа к Sentinel Hub (нужны ключи)
python make_snapshot.py       # обновить сохранённый снимок реальных данных (нужны ключи)
pip install -r requirements-dev.txt && pytest -q    # автотесты расчётной части
```

Доступ к Copernicus Data Space Ecosystem: ключи лежат в `config.py`. Чтобы
использовать другой OAuth-клиент, задайте переменные окружения — они имеют
приоритет над значениями из файла:

```bash
# Windows cmd (без кавычек!)
set SH_CLIENT_ID=...
set SH_CLIENT_SECRET=...
# Windows PowerShell
$env:SH_CLIENT_ID="..."; $env:SH_CLIENT_SECRET="..."
# Linux / macOS
export SH_CLIENT_ID="..." SH_CLIENT_SECRET="..."
```

## Режимы работы

**Реальные данные (сохранённый снимок)** — настоящий ряд NDVI/NDMI, история за
прошлые сезоны и растры NDVI, один раз полученные из Copernicus и сохранённые в
`data/snapshot/`. Воспроизводится на любой машине без ключей. Контур поля и границы
сезона берутся из снимка. Обновляется командой `python make_snapshot.py`
(`--field my_field.geojson` — свой контур).

**Demo** — синтетический сезон с заложенной аномалией и синтетический растр.
Работает мгновенно, без интернета и без расхода лимитов аккаунта. В интерфейсе
помечен оранжевой плашкой «ДЕМО-ДАННЫЕ».

**Реальные данные (Sentinel Hub)** — живые запросы к Copernicus Data Space по выбранному контуру.
Первый расчёт занимает 10-30 секунд, растровый слой — отдельный запрос. Если
получить данные не удалось, приложение показывает демо-данные, но при этом
выводит красную плашку с причиной: молча подменять результат нельзя.

Свой контур загружается файлом GeoJSON (Polygon или FeatureCollection с одним
полигоном), например нарисованный на https://geojson.io на спутниковой подложке.

## Что считает приложение

| Показатель | Как получается |
|---|---|
| Временной ряд NDVI/NDMI | Statistical API, агрегация по декадам, маска SCL отсекает облака и тени |
| Норма | Среднее NDVI той же декады за 3 прошлых сезона по этому же полю; при нехватке истории — среднее по текущему сезону |
| Проблемный период | Отклонение от нормы ниже `ANOMALY_THRESHOLD`, падение не меньше `MIN_ABS_DROP`, покрытие снимком не ниже `MIN_VALID_SHARE` |
| Достоверность периода | Доля валидных пикселей = (sampleCount − noDataCount) / sampleCount |
| Растр NDVI | Process API, GeoTIFF float32 по пикселям, наименее облачный снимок в окне ±5 дней |
| Проблемные зоны | Пиксели посевов, которые ниже медианы поля на 15% и одновременно больше чем на 2 робастных σ (1.4826·MAD); вода, глубокая тень и постройки (NDVI < 0.10) исключаются |
| Векторные контуры | Связные области проблемных пикселей → полигоны (маршевые квадраты + упрощение Дугласа-Пойкера), мельче 0,3 га отбрасываются |
| Площадь зон | Доля пикселей зоны среди валидных × площадь контура (формула шнурков) |
| Прогноз NDVI | Линейная регрессия по последним 5 наблюдениям, интервал предсказания по t-распределению, физический предел [0.05, 0.95] |
| Риск | Прогноз относительно нормы той же декады и скорость падения относительно падения самой нормы |
| Сравнение сезонов | Среднее NDVI по декадам, надёжным в обоих сезонах |
| Тип аномалии | Правило по совместному поведению NDVI и NDMI |
| Проверка прогноза | Backtest скользящим окном по всем сезонам: обучение на 5 снимках, прогноз на 14 дней, сравнение с фактом (интерполяция между снимками). Сравнение с базовыми моделями: «как сейчас», норма декады, «как сейчас + сезонное изменение», смесь. Норма для каждого сезона считается по другим сезонам |

## Структура

| Файл | Назначение |
|---|---|
| `config.py` | Доступы, контур поля по умолчанию, параметры сезона и порог |
| `sentinel_client.py` | Statistical API — временные ряды индексов |
| `raster.py` | Process API — растр NDVI, раскраска, статистика зон, векторные контуры зон, площадь |
| `analysis.py` | Норма сезона, отклонения, флаг проблемного периода |
| `ai_analysis.py` | Прогноз NDVI и классификация причины аномалии |
| `backtest.py` | Проверка прогноза на «будущих» данных и сравнение с базовыми моделями |
| `data_cache.py` | Сохранённый снимок реальных данных (чтение и запись) |
| `make_snapshot.py` | Получить реальные данные один раз и сохранить в `data/snapshot/` |
| `export.py` | Отчёт в CSV, GeoJSON и PDF |
| `i18n.py` | Тексты интерфейса на русском и казахском |
| `mock_data.py` | Синтетические данные для demo-режима |
| `app.py` | Интерфейс Streamlit |
| `test_connection.py` | Проверка доступа к API без запуска интерфейса |
| `tests/` | Автотесты расчётной части (норма, аномалии, прогноз, backtest, кэш, растр, переводы) |
| `.streamlit/config.toml` | Тема и настройки сервера Streamlit |

## Ограничения текущей версии

- Историческая норма строится по 3 прошлым сезонам; для полей с нестабильным севооборотом
  (разные культуры по годам) это грубое приближение — идеально сравнивать с теми же культурами.
- Классификация причины аномалии — экспертное правило, а не обученная модель.
- Растр строится на одну выбранную дату, без пролистывания по сезону.
- Метрики R², MAE, RMSE рядом с прогнозом считаются на тех же 5 точках, по которым построена модель, и описывают только посадку линии. Качество прогноза оценивается блоком backtest (вкладка «AI-прогноз»); на коротких рядах 15-18 точек его выборка небольшая, а линейный тренд может уступать наивному «как сейчас» — блок показывает это прямо.
- Контур по умолчанию — рамка, а не граница поля: лесополосы, водоёмы и дороги внутри неё искажают оценку зон. Для отчёта нужен настоящий контур.
- Интерфейс рассчитан на одно поле за раз.

## Развитие

1. Учёт севооборота: сравнение с прошлыми сезонами, когда на поле росла та же культура.
2. Пролистывание растра по датам сезона и карта изменения NDVI между двумя датами.
3. Несколько полей одновременно, загрузка shapefile с набором контуров.
4. Уведомления агроному при появлении новой зоны отклонения.
